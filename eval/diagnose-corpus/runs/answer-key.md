# Arm A vs C — prompt + answer key

Generated by `scripts/eval/run-harness.ts`. For each corpus fixture this pairs the exact
**prompt** to give the agent with the **gold** answer you score against. Use it alongside
`scoring-sheet.csv` (one row per session) and the client/arm setup in
`docs/agentic-mcp/diagnose-eval-harness.md`.

## Preparing each arm (command level)

The two clients live in different apps. Prep once, then **batch by (client, arm)** — toggle the
tool once per batch and start a fresh session per fixture. Run everything from the **repo root**.

### Claude Code (a terminal)

One-time build:

```bash
cd "$(git rev-parse --show-toplevel)"   # the triforge repo root (where .mcp.json lives)
npm run mcp:build                        # builds dist/mcp/server.cjs that .mcp.json points to
```

**Arm A (tool ON):**

```bash
cd "$(git rev-parse --show-toplevel)"
ls .mcp.json                             # must exist; if renamed: mv .mcp.json.off .mcp.json
claude                                   # start Claude Code FROM the repo root
# approve the "triforge" server if prompted, then type:  /mcp   (confirm it is connected)
```
Paste a fixture Prompt, let it finish, then snapshot the transcript and reset for the next fixture:
```bash
cp dist/mcp/claude-transcript.jsonl eval/diagnose-corpus/runs/transcripts/claude_A_<fixture>_t<trial>.jsonl
: > dist/mcp/claude-transcript.jsonl     # empty it so the next fixture is isolated
```
Type `/clear` between fixtures (fresh session).

**Switch to Arm C (tool OFF):**

```bash
# quit Claude Code (Ctrl-D), then hide the MCP config so nothing connects:
mv .mcp.json .mcp.json.off
claude                                   # start again from the repo root
/mcp                                     # confirm: NO servers connected
```
Paste each Prompt, `/clear` between fixtures, and save the conversation to
`eval/diagnose-corpus/runs/transcripts/claude_C_<fixture>_t<trial>.md`. When done, restore Arm A:
```bash
mv .mcp.json.off .mcp.json
```

### GitHub Copilot (VS Code Chat, Agent mode)

One-time build + load the extension:

```bash
cd "$(git rev-parse --show-toplevel)"
npm install                              # if not already done
npm run compile                          # build the extension (webpack)
```
Then load it in VS Code — either install the packaged `.vsix`, or open this folder in VS Code and
press **F5** ("Run Extension") to launch the Extension Development Host. In that window, **open
the triforge repo folder** as the workspace.

**Arm A (tool ON):**

- Open the **Chat** view → set the mode dropdown to **Agent**.
- Click **Configure Tools** → ensure **`triforge_diagnose_project` is CHECKED**.
- Paste a fixture Prompt as the first message. Start a **New Chat (＋)** per fixture.
- Export/copy each chat to `eval/diagnose-corpus/runs/transcripts/copilot_A_<fixture>_t<trial>.md`.

**Switch to Arm C (tool OFF):**

- **Configure Tools** → **UNCHECK `triforge_diagnose_project`** (Copilot keeps its file/terminal
  tools, just no diagnose tool).
- Paste each Prompt; **New Chat (＋)** per fixture; save to `copilot_C_<fixture>_t<trial>.md`.

## How to run one session

1. **Pick the next unrun row** in `scoring-sheet.csv`: a `client` (claude/copilot), `arm`
   (A/C), `fixture`, and `trial`.
2. **Set up that client + arm** per the setup matrix in the checklist — in **Arm A**
   `diagnose_project` is connected; in **Arm C** it is the *same* agent with the tool removed
   (repo checkout + shell only). Start a **fresh** session so nothing carries over from the
   previous fixture. Run from the **repo root** so the relative fixture path resolves.
3. **Find this fixture's block below and copy the Prompt verbatim** — the text after `> `,
   nothing added, nothing paraphrased. It is the agent's *first and only* instruction.
   (Expectation fixtures already have the user's expectation baked into the prompt — paste
   as-is.)
4. **Let the agent work** to a conclusion. In Arm A it may call the tool; in Arm C it must
   reason unaided. Do not coach it, and **do not reveal the gold** (it is collapsed below to
   help you avoid this).
5. **Save the transcript** to `runs/transcripts/<client>_<arm>_<fixture>_t<trial>.md`
   (or `.jsonl` for Claude's MCP tool-call log).
6. **Score the row** against the gold and fill the CSV (next section).

## How to score against the gold

- **found_fault (Y/N)** — did the agent identify the fault the `gold finding` names, *by
  meaning* (Arm C will not use the tool's exact wording)? For a **clean** fixture, Y means it
  correctly reported **no structural fault** — inventing one is N.
- **right_stage (Y/N)** — did it point at the artifact / pipeline stage in the gold
  *right artifact / stage*? Leave blank / `n/a` for clean fixtures.
- **turns** — agent turns to reach the answer. **false_claims** — count of wrong assertions
  about TRITON. **called_tool** (Arm A only) — did it actually invoke `diagnose_project`?

**Rules that keep the study valid:** never show the gold to the agent; never edit the prompt;
one fresh session per cell. **Clean fixtures use the same "it's broken" prompt on purpose** — a
false-premise robustness check; the correct answer is *"no structural fault found"*.
